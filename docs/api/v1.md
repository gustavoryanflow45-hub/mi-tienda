# API v1 — apps móviles (compradores y vendedores)

Base: `https://<tu-dominio>/api/v1` (en local, `http://127.0.0.1:8000/api/v1`).

Solo para **compradores y vendedores** (`users`). El panel de administración no
tiene endpoints aquí ni los tendrá: si algún día necesita API será otra
(`/admin-api`) con su propio guard. `tests/Feature/Api/V1/ApiRoutesTest.php`
falla si una ruta de `/api` toca el panel.

> Estado: **2a — autenticación**, **2b — catálogo** y **2c — carrito,
> checkout y pagos**. Perfil y endpoints de vendedor (2d) y la especificación
> OpenAPI (2e) llegan en las siguientes sub-fases.

---

## Convenciones

**Cabeceras de cada petición**

| Cabecera | Valor |
|---|---|
| `Accept` | `application/json` (recomendado; la API responde JSON aunque falte) |
| `Content-Type` | `application/json` en los POST con cuerpo |
| `Authorization` | `Bearer <token>` en los endpoints con 🔒 |
| `Accept-Language` | `es` (por defecto) o `en`. Los mensajes `message` salen en ese idioma; la respuesta trae `Content-Language`. |

**Respuestas correctas**

- Un recurso: `{ "data": { ... } }`
- Una lista: `{ "data": [ ... ] }`; las paginadas añaden `links` (`first`, `last`, `prev`, `next`) y `meta` (`current_page`, `last_page`, `per_page`, `total`…)
- Una acción sin recurso: `{ "message": "..." }` con 202, o `204` sin cuerpo.

**Errores** — siempre el mismo formato:

```json
{ "message": "Texto para mostrar al usuario", "code": "codigo_estable" }
```

Las validaciones añaden `errors` por campo:

```json
{
  "message": "Los datos enviados no son válidos.",
  "code": "validation_failed",
  "errors": { "email": ["El campo correo electrónico es obligatorio."] }
}
```

La app debe decidir por **`code`**, nunca por el texto (va traducido).

| HTTP | `code` | Cuándo |
|---|---|---|
| 401 | `unauthenticated` | Sin token, token revocado o **caducado** → ir al login |
| 401 | `invalid_credentials` | Login con correo o contraseña incorrectos |
| 403 | `email_not_verified` | Login de una cuenta sin verificar → ofrecer reenviar el correo |
| 403 | `account_disabled` | Cuenta bloqueada (también si se bloquea con la sesión abierta: el token se revoca) |
| 403 | `forbidden` | El token no tiene la habilidad necesaria |
| 404 | `not_found` | Ruta o recurso inexistente (o ajeno: nunca se confirma que existe) |
| 405 | `method_not_allowed` | Verbo HTTP incorrecto |
| 422 | `validation_failed` | Datos inválidos; ver `errors` |
| 409 | `payment_in_progress` | El pedido ya tiene un cobro en curso o hecho en Stripe: no reintentar, consultar el pedido |
| 422 | `business_rule` | La operación no procede en el estado actual (p. ej. una talla agotada, un pedido ya pagado, un pago rechazado) |
| 429 | `too_many_requests` | Límite de peticiones; esperar `Retry-After` segundos |
| 503 | `http_error` | Pasarela sin configurar en el servidor |

**Límites**

| Grupo | Límite |
|---|---|
| Toda la API | 60 peticiones/min por usuario (o por IP sin token) |
| `register`, `login`, `email/resend`, `password/forgot` | 5/min por correo+IP y 20/min por IP |
| `/cart*` | 120/min por usuario, **compartido con el carrito web** |
| `POST /checkout/orders` | 30/min por usuario, compartido con el checkout web |
| Iniciar un cobro (`…/stripe`, `…/payphone`) | 10/min por usuario y 30/min por IP, compartido con la web. Confirmar no tiene límite propio |

## Sesiones por dispositivo

- Cada login crea un **token por dispositivo**. La app genera un `device_id`
  estable al instalarse (un UUID guardado en almacenamiento seguro) y lo manda
  siempre: volver a entrar desde el mismo dispositivo **reemplaza** su token.
- Los tokens **caducan** a los 30 días (`API_TOKEN_TTL_DAYS`). La app debe
  **rotarlo** (`POST /auth/token/rotate`) al abrirse si quedan menos de ~7 días
  para `expires_at`: así una sesión en uso no caduca nunca y un móvil
  olvidado se cierra solo.
- Como mucho 10 dispositivos por cuenta (`API_MAX_DEVICES`); al pasarse, el
  login cierra la sesión menos usada.
- El usuario ve sus sesiones y puede cerrar cualquiera (`/auth/devices`).
- Guarda el token en **almacenamiento seguro** (Keychain / Keystore, p. ej.
  `flutter_secure_storage`), nunca en preferencias planas. En la base solo
  queda su hash.

**Habilidades (abilities)** del token según el rol:

| Rol | Habilidades |
|---|---|
| Comprador (y vendedor sin tienda aprobada) | `profile:read`, `profile:write`, `cart:write`, `checkout:write`, `orders:read` |
| Vendedor con tienda aprobada | lo anterior + `seller:products`, `seller:orders` |

Se calculan al emitir o rotar el token: si un vendedor recibe la aprobación de
su tienda, obtiene las de vendedor en su siguiente rotación. Ningún token tiene
habilidades de administración.

## Endpoints

### `POST /auth/register`

Alta de **comprador**. No devuelve token: hay que verificar el correo (el
enlace del email abre la web) y luego hacer login.

```json
{ "name": "Ana Pérez", "email": "ana@correo.com",
  "password": "Clave1234", "password_confirmation": "Clave1234",
  "phone": "+593 99 999 9999" }
```

Contraseña: mínimo 8 caracteres con letras y números. Cualquier otro campo
(`user_type`, `balance`…) se ignora.

`201`:

```json
{ "data": { "id": 7, "name": "Ana Pérez", "email": "ana@correo.com", "phone": "+593 99 999 9999",
            "avatar_url": null, "type": "customer", "email_verified": false, "balance": 0,
            "shop": null, "created_at": "2026-11-05T10:00:00-05:00" },
  "message": "Cuenta creada. Te enviamos un enlace para verificar tu correo; después podrás iniciar sesión." }
```

Errores: `422 validation_failed` (correo repetido, contraseña débil…).

### `POST /auth/login`

```json
{ "email": "ana@correo.com", "password": "Clave1234",
  "device_id": "3f2a9c1e-5b7d-4e8f-9a0b-1c2d3e4f5a6b", "device_name": "Pixel 8 de Ana" }
```

`device_id`: letras, números y `. _ : -`, máx. 100. `200`:

```json
{ "data": {
    "token": "12|Qm9n…",
    "token_type": "Bearer",
    "expires_at": "2026-12-05T10:00:00-05:00",
    "abilities": ["profile:read", "profile:write", "cart:write", "checkout:write", "orders:read"],
    "device": { "id": 12, "device_id": "3f2a9c1e-…", "device_name": "Pixel 8 de Ana" },
    "user": { "id": 7, "name": "Ana Pérez", "type": "customer", "...": "..." } } }
```

Errores: `401 invalid_credentials` (igual exista o no el correo),
`403 email_not_verified`, `403 account_disabled`, `429 too_many_requests`.

### `GET /auth/me` 🔒 `profile:read`

El usuario del token. `meta.abilities` lista las habilidades del token actual.

### `POST /auth/token/rotate` 🔒

Sin cuerpo. Devuelve un token nuevo (mismo formato que el login) para el mismo
dispositivo, con la caducidad renovada y las habilidades recalculadas. **El
token anterior deja de valer en el acto**: guarda el nuevo antes de hacer otra
petición.

### `POST /auth/logout` 🔒

Revoca el token de este dispositivo. `204`.

### `GET /auth/devices` 🔒

```json
{ "data": [
  { "id": 12, "device_id": "3f2a…", "device_name": "Pixel 8 de Ana", "abilities": ["..."],
    "current": true, "last_used_at": "2026-11-05T10:05:00-05:00",
    "created_at": "2026-11-05T10:00:00-05:00", "expires_at": "2026-12-05T10:00:00-05:00" } ] }
```

Nunca incluye el token.

### `DELETE /auth/devices/{id}` 🔒

Cierra la sesión de ese dispositivo (un `id` de la lista). `204`; `404` si no
es de esta cuenta.

### `DELETE /auth/devices` 🔒

Cierra **todas las demás** sesiones. Con `?include_current=1`, también esta.
`204`.

### `POST /auth/email/resend`

`{ "email": "ana@correo.com" }` → `202` con el mismo mensaje exista o no la
cuenta.

### `POST /auth/password/forgot`

`{ "email": "ana@correo.com" }` → `202` con el mismo mensaje exista o no la
cuenta. El enlace del correo abre la web para elegir la contraseña nueva. Si se
pide dos veces en menos de 60 s: `429 too_many_requests`.

## Catálogo (público, sin token)

Solo productos **a la venta**: publicados por su vendedor y no desactivados por
la moderación. Uno que no lo está responde `404 not_found`, igual que en la
web. Los precios van en la moneda de la tienda con dos decimales.

### `GET /home`

La portada en una petición: `banners` (imagen y enlace), `featured`, `new` y
`best_selling` (hasta 12 productos cada una, formato tarjeta).

### `GET /categories`

Árbol de categorías activas en el orden del menú de la tienda: cada raíz con
sus `children` activas. `{ id, name, slug, parent_id, icon_url, banner_url, children[] }`.

### `GET /categories/{slug}`

Una categoría con sus `children` y su `parent`. Sus productos se piden con
`/products?category={slug}`.

### `GET /brands`

Marcas activas: `{ id, name, slug, logo_url }`.

### `GET /products`

Listado paginado de tarjetas. Parámetros (todos opcionales):

| Parámetro | |
|---|---|
| `q` | Texto a buscar en el nombre (sin distinguir mayúsculas), máx. 100 |
| `category` | Slug de una categoría activa; **incluye sus subcategorías**. Inexistente → 422 |
| `brand` | Id de una marca activa |
| `min_price`, `max_price` | Rango sobre el precio del producto (`max_price` ≥ `min_price`) |
| `featured` | `1` = solo destacados |
| `sort` | `newest` (por defecto), `price_asc`, `price_desc`, `popular`, `rating` |
| `per_page` | 1–50 (por defecto 20) |
| `page` | Página, desde 1 |

Son los mismos filtros que la página de categoría de la web
(`CatalogService`). Respuesta:

```json
{ "data": [
    { "id": 3, "slug": "zapatos-adidas-terrex", "name": "Zapatos Adidas Terrex",
      "thumbnail_url": "https://…/storage/products/thumbnails/….webp",
      "price": 65.0, "original_price": 65.0, "discount": null,
      "unit": "par", "rating": 0, "in_stock": true, "has_variants": true,
      "category": { "id": 4, "name": "Deportes y aire libre", "slug": "deportes-y-aire-libre" },
      "brand": null } ],
  "links": { "first": "…", "last": "…", "prev": null, "next": "…" },
  "meta": { "current_page": 1, "last_page": 1, "per_page": 20, "total": 3, "…": "…" } }
```

- `price` es **lo que se cobra** (con el descuento aplicado); `original_price`,
  el de antes. Con descuento: `"discount": { "type": "percent" | "amount", "value": 10 }`.
- `has_variants: true` → hay que elegir una combinación en la ficha antes de
  añadir al carrito.

### `GET /products/{slug}` (o `/products/{id}`)

La tarjeta más:

```json
{ "photos": ["https://…/storage/products/photos/….webp"],
  "short_description": "…",
  "description": "Texto plano: el HTML del vendedor se convierte a párrafos.",
  "min_qty": 1, "shipping_cost": 0,
  "shop": { "id": 1, "name": "Tienda de Ana" },
  "variants": {
    "size_label": "Talla US",
    "sizes": ["9", "10"],
    "colors": [{ "key": "negro", "label": "Negro", "hex": "#000000" }],
    "combinations": [
      { "variation": "9-negro", "size": "9", "color": "negro",
        "price": 58.5, "original_price": 65.0, "qty": 4, "available": true },
      { "variation": "10-negro", "size": "10", "color": "negro",
        "price": 58.5, "original_price": 65.0, "qty": 0, "available": false } ] },
  "related": [ { "…tarjeta…": "" } ] }
```

- Las combinaciones son exactamente las de la ficha web: la app no puede
  ofrecer una que la web ya no tiene. Desactiva en el selector las que tengan
  `available: false` y muestra el `price` de la elegida.
- **`variation` es la clave que pide el carrito** (`POST /cart/items`) para esa combinación.
  Producto sin variantes: `combinations` trae una sola entrada con
  `variation: ""`.
- `size_label` y las etiquetas de color salen en el idioma de `Accept-Language`.

## Carrito 🔒 `cart:write`

Es **el mismo carrito que el de la web** (lo que se añade en la app aparece en
la web y al revés) y con las mismas reglas: solo productos a la venta, una
combinación que exista, sin pasar del stock. Todas las respuestas traen el
carrito completo:

```json
{ "data": {
    "items": [
      { "id": 41,
        "product": { "id": 3, "slug": "zapatos-adidas-terrex", "name": "Zapatos Adidas Terrex",
                     "thumbnail_url": "https://…", "on_sale": true },
        "variation": "9-negro",
        "variant": { "text": "Talla US 9 · Negro", "size": "9", "size_label": "Talla US",
                     "color": "negro", "color_label": "Negro", "color_hex": "#000000" },
        "price": 58.5, "quantity": 2, "line_total": 117.0, "shipping_cost": 0,
        "available_qty": 4 } ],
    "count": 2,
    "totals": { "subtotal": 117.0, "shipping": 0, "tax": 0, "grand_total": 117.0 },
    "currency": "USD" } }
```

- `price` es el precio unitario **fijado al añadir** la línea (con descuento).
- `variant` es `null` en un producto sin variantes. Muestra `variant.text`;
  `variation` es la clave interna.
- `available_qty`: tope para el selector de cantidad.
- `product.on_sale: false` → el producto se despublicó o se vetó después de
  añadirlo; la línea sigue en el carrito (como en la web), pero conviene
  avisar y ofrecer quitarla.
- Envío: costo fijo por línea (no por unidad), definido por el vendedor.

### `GET /cart`

El carrito.

### `POST /cart/items`

```json
{ "product_id": 3, "variation": "9-negro", "quantity": 2 }
```

`variation` es la de `variants.combinations` en la ficha (`""` o ausente en un
producto sin variantes); `quantity` 1–999, por defecto 1. Si la línea ya
existe se suman las unidades, con tope en el stock. `201` con el carrito y
`message`.

Errores: `404` producto inexistente o no a la venta; `422 business_rule` sin
combinación elegida, combinación inexistente, agotada o más unidades de las
que hay (el `message` lo explica).

### `PATCH /cart/items/{id}`

`{ "quantity": 5 }`. Se limita al stock: la respuesta trae la cantidad real.

### `DELETE /cart/items/{id}`

Quita la línea. `404` si no es de esta cuenta.

### `DELETE /cart`

Vacía el carrito. `204`.

## Checkout y pagos 🔒 `checkout:write`

Flujo:

1. `GET /checkout` — resumen y datos de envío del perfil para rellenar el
   formulario. No crea nada.
2. `POST /checkout/orders` — crea el **pedido pendiente** con los datos de
   envío. Guarda su `id`: se reenvía como `order_id` si el comprador vuelve
   atrás y cambia algo, para no acumular pedidos.
3. Cobro con la pasarela elegida (abajo). Iniciar un cobro **vuelve a
   sincronizar el pedido con el carrito**: se cobra lo que hay en el carrito
   en ese momento.
4. `GET /checkout/orders/{id}` — estado final. Al pagarse, el carrito se vacía.

### `GET /checkout`

```json
{ "data": {
    "items": [ "…líneas del carrito…" ],
    "totals": { "subtotal": 117.0, "shipping": 0, "tax": 0, "grand_total": 117.0 },
    "currency": "USD",
    "shipping": { "full_name": "Ana Pérez", "phone": "…", "email": "…", "address": "…",
                  "city": "Quito", "state": null, "country": null, "postal_code": null },
    "payment": { "suggested_gateway": "payphone", "country": "EC",
                 "gateways": ["stripe", "payphone"], "stripe_publishable_key": "pk_live_…" } } }
```

`suggested_gateway` sale del país de la IP, como en la web: PayPhone en
Ecuador, Stripe en el resto. La app puede ofrecer cualquiera de `gateways`.
Carrito vacío: `422 business_rule`.

### `POST /checkout/orders`

```json
{ "full_name": "Ana Pérez", "phone": "0999999999", "email": "ana@correo.com",
  "address": "Av. Amazonas 123", "city": "Quito",
  "state": "Pichincha", "country": "Ecuador", "postal_code": "170150",
  "order_id": 88 }
```

Obligatorios `full_name`, `phone`, `email`, `address` y `city`; `order_id` es
opcional (si es un pedido propio sin pagar se pone al día; si no, se crea
otro). La dirección queda como la predeterminada del comprador. `201` si se
creó, `200` si se reutilizó; el cuerpo es el pedido:

```json
{ "data": {
    "id": 88, "code": "ORD-20261105-1A2B3C",
    "payment_status": "unpaid", "payment_status_label": "Sin pagar",
    "payment_gateway": null,
    "delivery_status": "pending", "delivery_status_label": "Pendiente",
    "currency": "USD",
    "totals": { "subtotal": 117.0, "shipping": 0, "tax": 0, "grand_total": 117.0 },
    "shipping_address": { "full_name": "Ana Pérez", "…": "…" },
    "items": [ { "id": 301, "product_id": 3, "name": "Zapatos Adidas Terrex", "thumbnail_url": "…",
                 "variation": "9-negro", "variant": { "text": "Talla US 9 · Negro", "…": "…" },
                 "price": 58.5, "quantity": 2, "line_total": 117.0, "shipping_cost": 0 } ],
    "created_at": "2026-11-05T10:00:00-05:00", "paid_at": null } }
```

### `GET /checkout/orders/{id}`

El pedido (mismo formato). `payment_status: "paid"` = cobrado. `404` si no es
de esta cuenta.

### Stripe

**`POST /checkout/orders/{id}/stripe`** — sin cuerpo:

```json
{ "data": { "client_secret": "pi_…_secret_…", "payment_intent_id": "pi_…",
            "publishable_key": "pk_live_…", "amount": 11700, "currency": "usd",
            "order": { "…pedido…": "" } } }
```

Con `flutter_stripe`: `Stripe.publishableKey = publishable_key`,
`initPaymentSheet(paymentIntentClientSecret: client_secret, …)` y
`presentPaymentSheet()`. Reintentar reutiliza el mismo PaymentIntent.
`409 payment_in_progress` si ya hay un cobro en curso o hecho: no reintentes,
consulta el pedido.

**`POST /checkout/orders/{id}/stripe/confirm`** — sin cuerpo, al cerrarse la
PaymentSheet con éxito. El servidor consulta el pago en Stripe y devuelve el
pedido; mira `payment_status`. (El webhook de Stripe también lo registra; esto
evita esperarlo.)

### PayPhone (Ecuador)

PayPhone no tiene SDK: se paga en su página, en un **navegador in-app**.

**`POST /checkout/orders/{id}/payphone`** — `{ "method": "card" }` (tarjeta) o
`"app"` (saldo de la app de PayPhone):

```json
{ "data": { "redirect_url": "https://pay.payphonetodoesposible.com/…",
            "client_transaction_id": "GA88-K3J9X0QW2Z",
            "return_url": "mitienda://payment-result",
            "order": { "…pedido…": "" } } }
```

1. Abre `redirect_url` con `flutter_web_auth_2` (ASWebAuthenticationSession /
   Custom Tab) usando como `callbackUrlScheme` el esquema de `return_url`
   (`mitienda`).
2. Tras pagar, PayPhone vuelve al servidor, que **confirma el cobro** y
   redirige a `mitienda://payment-result?status=paid&order=88`. `status` puede
   ser `paid`, `canceled` (rechazado o abandonado), `error`, `mismatch` (el
   monto no coincide: soporte) o `unknown`.
3. Sea cual sea el `status`, consulta `GET /checkout/orders/{id}`: lo que vale
   es el estado del pedido.

**`POST /checkout/orders/{id}/payphone/confirm`** — por si la app cortó la
navegación antes de que el servidor confirmara:
`{ "id": 555, "client_transaction_id": "GA88-K3J9X0QW2Z" }` (los parámetros
`id` y `clientTransactionId` de la URL de vuelta de PayPhone). Devuelve el
pedido pagado, o `422 business_rule` si PayPhone lo rechazó; `404` si la
transacción no es de ese pedido. Se puede llamar aunque el servidor ya lo
haya confirmado. **Si nadie confirma en 5 minutos, PayPhone revierte el
cobro.**

## Notas para Flutter

- **Cliente HTTP**: un interceptor (p. ej. `dio`) que añada `Authorization`,
  `Accept` y `Accept-Language`, y que ante `401 unauthenticated` borre el
  token y lleve al login.
- **Rotación**: al abrir la app, si `expires_at - ahora < 7 días`, llamar a
  `/auth/token/rotate` antes de nada y guardar el token nuevo.
- **Pagos**: Stripe con `flutter_stripe` (PaymentSheet) y PayPhone con
  `flutter_web_auth_2` y el esquema `mitienda://` (el servidor lo toma de
  `API_APP_PAYMENT_RETURN_URL`; la app debe registrar el mismo). Ver
  **Checkout y pagos**.
